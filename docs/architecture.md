# Architecture

```
src/imigraph/
  trajectory.py            Trajectory / Box: the common format of every system (positions over time)
  reference/brownian.py    BrownianBox: the trusted reference system (Euler-Maruyama, reflecting walls)
  graph/space.py           Space protocol, SquareLattice (neighbour table + 2D coordinates)
  graph/state.py           WalkerGraph: space nodes + walker nodes, one anchoring edge per walker
  graph/rules.py           Rule protocol, RandomHop ({w,s},{s,s'} -> {w,s'},{s,s'})
  graph/simulation.py      GraphSimulation.run -> GraphHistory; GraphHistory.project -> Trajectory
  compare/checks.py        MsdCheck, MarginalKsCheck, OccupancyCheck (Check protocol)
  compare/framework.py     compare(reference, candidate) -> ComparisonReport
  experiments/             ExperimentConfig + run_experiment: both systems from one config
  report/svg.py            SVG line charts, histograms, heatmaps (no plotting library)
  report/html.py           self-contained HTML report (assets/report.html, viz.js, report.css)
  report/live.py           entry point of the browser GUI (JSON in, JSON out)
  __main__.py              python -m imigraph {compare,report}
web/                       Pyodide GUI (index.html, app.js); dist/ is generated by docker/serve-web.sh
docker/                    compose entrypoints, container git hook, headless page check
docs/, plans/              requirements, methods, plans
.claude/skills/            project skills for coding agents
```

## Layers

1. **Systems** produce a `Trajectory`: times `(T,)`, positions `(T, n, 2)`, a `Box`. The
   reference system does so directly; a graph system does so through a *projection*.
2. **Graph systems** are a static `Space` (a graph whose nodes carry 2D coordinates and whose
   edges are stored as a dense neighbour table), a `WalkerGraph` state (which space node each
   walker node is attached to) and a `Rule` that rewrites the walker edges. `GraphSimulation`
   applies the rule step by step and records a `GraphHistory`; `GraphHistory.project()` turns it
   into a `Trajectory`.
3. **Comparison** consumes two trajectories recorded at the same times and runs checks, each
   with an explicit threshold (`docs/comparison-method.md`).
4. **Experiments** tie a reference system and a graph system to one configuration, with the
   physical parameters derived once (`D = a^2 / (4 tau)`).
5. **Presentation** (HTML report, browser GUI) only consumes experiment results. Numerical code
   never imports presentation code.

## Rules of the code base

- Numerical cores depend on numpy and scipy only; networkx is imported lazily for graph views.
  This keeps the same modules running under pytest and under Pyodide.
- Randomness is explicit: every function that draws random numbers takes a
  `numpy.random.Generator`. Experiments spawn independent streams per system from one seed.
- Vectorised updates: one rule application is O(number of walkers) numpy work, no Python loop
  over walkers. Space graphs expose a neighbour table `(num_nodes, degree)` for that.
- The physical meaning of a graph system is stated in code: `lattice_hop_diffusion()` is the
  formula the experiment uses to run the reference with the matching diffusion coefficient.

## The first graph system in detail

- Space: `L x L` square lattice, spacing `a`, node `(i, j)` at `(i a, j a)`. Boundary nodes get
  self-loops for the neighbours they lack, so every node has four hop options. With self-loops
  the uniform distribution over nodes is stationary, which matches the uniform stationary
  density of Brownian motion in a box with reflecting walls.
- The box of the projection extends `a / 2` beyond the outer nodes so that every node owns a cell
  of area `a^2`.
- State: the graph with space nodes `0 .. L^2 - 1` and walker nodes `L^2 .. L^2 + n - 1`, each
  walker joined to the space by one edge `{w, anchor[w]}`.
- Rule `RandomHop`: for every walker, pick one of the four edges at its anchor uniformly at
  random and move the walker edge along it. Synchronous update of all walkers.
- Initial condition: all walkers at the centre node; the reference starts all particles at the
  centre of the box.
- Projection: a walker sits at its node's coordinates. For distribution tests, each walker gets
  a fixed random offset inside its node's cell (`GraphHistory.project(cell_rng=...)`): the graph
  then claims to imitate the reference at resolution `a`. Displacements, and therefore the MSD,
  do not depend on the offset.

## Metrics: energy, momentum, entropy (`imigraph.metrics`)

Overdamped Brownian particles exchange energy and momentum with the bath, so neither is
conserved particle by particle; the *ensemble* values are stationary and that is what is
measured, for both systems alike:

- **Kinetic energy per particle** `m |dr|^2 / (2 dt^2)` averaged over particles at every
  simulation step (free value `2 m D / dt`, the temperature of the bath in these units).
- **Total momentum** `m sum(dr) / dt` at every step (mean zero, standard deviation
  `sqrt(2 n m^2 D / dt)` per component).
- **Occupancy entropy** `-sum p ln p` of a `bins x bins` histogram at every recorded frame
  (0 at the start, `ln(bins^2)` for a uniform occupancy; rises on average, fluctuates).

Two rule-level metrics complete the picture:

- **Wall interaction rate**: fraction of particles per step that were reflected (reference) or
  hopped along a self-loop (graph). Zero until the cloud reaches the walls, then stationary;
  the two systems discretise the wall differently, so the rates are similar but not identical.
- **Occupied cells** of the lattice grid (a walker occupies the cell of its node): rises from 1
  towards `cells^2 (1 - exp(-n / cells^2))` for a uniform occupancy, equally in both systems.

Energy and momentum come from a `StepObserver` the simulators call after every fine step,
then averaged per recording interval, because a particle that bounces off a wall between two
recorded frames would otherwise look like it lost energy. Walls do cost a little: in the
default experiment both systems sit about 2% below the free value, stationary, and agree with
each other within 1%. `tests/test_metrics.py` pins these statements.

## Second reference system: the hard-disk gas (`imigraph.reference.gas`)

Energy-conserving particle motion: disks in straight lines, elastic collisions (velocity
components along the line of centres exchanged, which conserves momentum and kinetic energy
exactly), specular or periodic walls, fixed time step (a collision is resolved at the first
step in which two disks overlap). `imigraph.experiments.gas` runs a free expansion from the left
half of the box and checks against kinetic theory: energy constant to rounding, momentum
constant (periodic) or bounded (specular walls), final speeds Maxwell-Boltzmann (Rayleigh with
`sigma^2 = E / (n m)`), occupancy entropy rising to the uniform value. Page:
`python -m imigraph gas-report`. No graph imitation yet: the natural candidate is a lattice gas
(HPP/FHP-style rules), which conserves mass, momentum and energy exactly by construction.

## Extending

- **New space**: implement the `Space` protocol (`coordinates`, `neighbors`, `box`,
  `cell_size`, `edges()`, `to_networkx()`). Keep the neighbour table dense (pad with self-loops
  or implement a weighted choice in the rule).
- **New rule**: implement `Rule.apply(state, rng) -> WalkerGraph` with numpy over all walkers.
- **New reference system**: return a `Trajectory`; document the analytic facts the tests use.
- **New check**: implement `Check.run(reference, candidate) -> CheckResult` and add it to the
  validation matrix in `tests/test_compare.py` (a pass case and at least one fail case).
- **Growing spaces** (the next step towards the Wolfram model): a rule that also adds nodes and
  edges needs a mutable space; the projection should then come from the graph itself (for
  example a spectral embedding of the graph Laplacian) instead of being given a priori.
